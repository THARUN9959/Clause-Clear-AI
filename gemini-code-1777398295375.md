## FULL ARCHITECTURE SPECIFICATION

### PHASE 1 — PERSISTENCE LAYER
Replace the in-memory MemoryManager in services/memory_service.py with
SQLite managed via SQLModel (pip install sqlmodel). SQLModel wraps
SQLAlchemy + Pydantic giving safe thread handling, validation, and no
raw SQL boilerplate.

Define these SQLModel table models in a new db.py:

  Session(session_id: str PK, created_at: datetime, last_accessed: datetime)
  Analysis(id: int PK, session_id: str FK, filename: str, contract_type: str,
    full_text: str, analysis_json: str, health_score: int, created_at: datetime, embedding: str)
  ChatHistory(id: int PK, session_id: str FK, analysis_id: int FK,
    role: str, content: str, timestamp: datetime)
  Obligation(id: int PK, analysis_id: int FK, obligation: str,
    deadline_description: str, party: str, section: str)

Use SQLModel's create_engine with connect_args={"check_same_thread": False}
and manage sessions via a get_session() dependency per request using Flask's
g object (g.db) — never a global connection.

Add a startup cleanup job (run once on app init) that deletes Session rows
older than 7 days and calls os.remove() on any associated files in uploads/.

### PHASE 2 — SINGLE UNIFIED GEMINI CALL (STRUCTURED OUTPUT)
IMPORTANT: Do NOT make separate API calls for classification, analysis,
obligation extraction, and scoring. Combine everything into one single
Gemini call per document using Gemini's response_schema (Structured Outputs)
to enforce a strict JSON response.

The single prompt must instruct Gemini to return this exact JSON structure:

{
  "contract_type": "NDA|EMPLOYMENT|SAAS_TOS|FREELANCE|RENTAL|LOAN|PARTNERSHIP|UNKNOWN",
  "health_score": <integer 0-100>,
  "health_grade": "A|B|C|D|F",
  "health_verdict": "<one sentence plain English verdict>",
  "risks": [
    {
      "clause": "<clause name>",
      "severity": "HIGH|MEDIUM|LOW",
      "explanation": "<plain English explanation with benchmark comparison>",
      "suggested_redline": "<one or two sentence proposed rewrite>"
    }
  ],
  "obligations": [
    {
      "obligation": "<obligation description>",
      "deadline_description": "<timing>",
      "party": "<responsible party>",
      "section": "<contract section>"
    }
  ],
  "summary": "<3-5 sentence plain language summary of the whole contract>",
  "key_entities": {
    "parties": [],
    "effective_date": "",
    "governing_law": "",
    "termination_notice": ""
  }
}

Build a PROMPT_TEMPLATES dict in gemini_service.py keyed by contract_type.
Each template is a specialized system prompt injected before the user
document. Specializations:

  NDA: focus on mutual vs one-sided scope, IP assignment breadth,
    residuals clauses, duration, jurisdiction
  EMPLOYMENT: at-will provisions, non-compete duration+geography,
    equity vesting cliff+acceleration, IP ownership of side projects,
    arbitration waivers
  SAAS_TOS: auto-renewal + cancellation notice windows, data ownership,
    liability caps, SLA definitions, unilateral modification rights
  FREELANCE: payment terms + kill fees, IP transfer timing, revision
    limits, non-solicit clauses
  RENTAL: security deposit conditions, early termination penalties,
    maintenance responsibilities, subletting rights
  UNKNOWN: use a balanced generic prompt

For contracts that arrive as UNKNOWN on first pass, run a lightweight
classify_only call first (single sentence output), then route to the
correct full template. This is the only case where two calls are allowed.

### PHASE 3 — BENCHMARK INJECTION
Create services/benchmark_service.py with a hardcoded
get_benchmark_context(contract_type) function returning a dict of
market standard ranges. Inject this into the system prompt so Gemini
explicitly compares each clause against market norms. Examples:

  EMPLOYMENT:
    non_compete_duration: "market standard 6–12 months; over 18 is aggressive"
    equity_vesting: "standard 4-year with 1-year cliff"
    ip_assignment: "standard covers work hours only; side projects should be excluded"
  NDA:
    duration: "standard 2–3 years; perpetual NDAs are non-standard"
    scope: "standard is confidential information exchanged for the project only"
  SAAS_TOS:
    auto_renewal_notice: "standard 30–60 days; under 15 days is a red flag"
    liability_cap: "standard is fees paid in last 12 months"
  FREELANCE:
    payment_terms: "standard net-30; beyond net-60 is unusual"
    kill_fee: "standard 25–50% of project value"
  RENTAL:
    security_deposit: "standard 1–2 months rent"
    notice_period: "standard 30 days for month-to-month"

The explanation field of each risk item MUST reference these benchmarks
explicitly (e.g., "This 24-month non-compete exceeds the market standard
of 6–12 months").

   debug=os.getenv("FLASK_DEBUG", "false").lower() == "true"

2. config.py: remove hardcoded SECRET_KEY fallback. Replace with:

   if not SECRET_KEY:
       raise RuntimeError("FLASK_SECRET_KEY environment variable is required")

3. static/js/app.js: replace ALL innerHTML assignments that render LLM

4. app.py upload route: after text extraction completes, immediately
   delete the uploaded file:
   finally:
       if os.path.exists(filepath):
           os.remove(filepath)
   Wrap ALL file reading in document_service.py in strict
   with open(...) as f: context managers to release Windows file locks
   before os.remove() is called.

5. Add Flask-WTF CSRF protection globally. Inject CSRF token into
   base.html as:
   <meta name="csrf-token" content="{{ csrf_token() }}">
   In app.js, read the token and include it as X-CSRFToken header on
   all POST fetch requests.

### PHASE 5 — INPUT VALIDATION & RATE LIMITING
In the upload route in app.py:
  - Enforce 10MB max file size; return 413 with user-facing message if exceeded
  - Whitelist extensions: .pdf, .docx, .png, .jpg, .jpeg only
  - Validate MIME type using python-magic (not just extension)
  - Sanitize filename using werkzeug.utils.secure_filename

Install and configure Flask-Limiter with in-memory storage:
  /api/upload:  10 requests/hour per IP
  /api/analyze: 10 requests/hour per IP
  /api/chat:    30 requests/hour per IP
Return proper HTTP 429 with a user-facing error message.

### PHASE 11 — LOADING STATES (REPLACES STREAMING)
Do NOT implement token-by-token streaming. Strict JSON structured output
is incompatible with token streaming. Instead implement a multi-stage
loading indicator:

On analyze.html, when analysis is triggered, show a loading overlay with
sequential status messages driven by a simple JS interval that cycles
through stages every 3 seconds:
  "Extracting document text..."
  "Classifying contract type..."
  "Analyzing clauses against market benchmarks..."
  "Identifying obligations and deadlines..."
  "Calculating health score..."
  "Finalizing report..."

Once the API response returns, hide the overlay and render all sections
at once. This is cleaner than broken partial JSON streaming.

### PHASE 16 — VANILLA RAG (HISTORICAL CONTEXT)
Using the existing Gemini SDK, call the `text-embedding-004` model.
When a contract is finalized, generate a single vector embedding for the 
combined text of its highest-severity risks. Store this vector as a JSON 
string in the `embedding` column of the `Analysis` table.

When a new contract is uploaded, embed its text. Fetch past embeddings 
from SQLite and calculate cosine similarity using pure Python (math module). 
Find the top 1 match. Inject this into the analysis prompt: 
"Historical Context: We have seen similar clauses before in past analyses 
that carried a health score of X."

Do not use ChromaDB, Pinecone, or FAISS. Strict adherence to SQLite and 
standard library math to maintain zero heavy dependencies.

## CRITICAL TECHNICAL GUARDRAILS — READ BEFORE WRITING ANY CODE
- Windows file locks: ALL file reading in document_service.py MUST use
  with open(...) as f: context managers. os.remove() must only be called
  inside a finally block after all file handles are guaranteed closed.

- PDF library: ONLY use fpdf2. DO NOT install weasyprint, pdfkit, or
  wkhtmltopdf. They require system-level GTK3 binaries unavailable on
  Windows without manual setup.

- SQLite thread safety: Use SQLModel with create_engine(connect_args=
  {"check_same_thread": False}). Manage DB sessions via Flask g object
  per request. Never use a single global connection object.

- JSON vs Streaming: Do NOT stream raw tokens. Use Gemini structured
  output (response_schema) for one clean JSON response. Use the JS
  loading stage animation instead.

- Single API call: Classification + analysis + obligations + health score
  MUST be one Gemini call. The only exception is UNKNOWN contract type
  requiring a pre-classification call.

- All DB operations: Wrap in try/except with session.rollback() on
  failure. Use SQLModel ORM only — no raw f-string SQL queries anywhere.

- Error handling: Every Gemini API call must have a try/except that
  returns a structured error JSON to the frontend. Never let a raw
  Python traceback reach the HTTP response.

- requirements.txt: Must be fully updated with pinned versions for all
  new dependencies: sqlmodel, fpdf2, flask-limiter, flask-wtf,
  python-magic, pillow, pytesseract, pypdf2, python-docx, google-genai

- .env must never be committed. Confirm .gitignore includes: .env,
  uploads/, logs/, __pycache__/, *.pyc, .sqlite
